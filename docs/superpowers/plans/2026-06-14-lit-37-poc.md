## Phase 2 — Feature 2: Expanded Path with Schema Customization

**Target:** Team (cross-team coordination required, different artifact rules)  
**Path:** `/opsx:new → /opsx:ff (or :continue) → /opsx:apply → /opsx:verify → /opsx:archive`  
**Feature description:** "Add team notification preferences — each team member can configure which lifecycle events trigger notifications (phase change, artifact created, review requested)"

This phase has a setup step: customize `config.yaml` for the Team target before running the workflow.

### Task 5: Customize config.yaml for Team Target

**Files:**
- Modify: `openspec/config.yaml`

- [ ] **Step 1: Edit config.yaml to add Team-target context and rules**

  Open `/Users/edgar.hernandez/Desktop/open-specs/openspec/config.yaml` and replace its contents with:

  ```yaml
  schema: spec-driven

  context: |
    Target: Team (cross-team coordination required)
    This project involves multiple teams. Changes that affect shared interfaces or cross-team contracts
    must include a "Stakeholders" section in the proposal identifying which teams are impacted.
    Use conventional commits. Document non-goals explicitly.

  rules:
    proposal:
      - Always include a "Stakeholders" section listing affected teams
      - Always include a "Non-goals" section
      - Keep proposals under 400 words
    tasks:
      - Break tasks into chunks of max 2 hours
      - Each task must identify its owner role (Frontend / Backend / Platform)
    spec:
      - Include an "Integration points" section for cross-team interfaces
  ```

  This customization is the AC#3 evidence: same tool, different target, achieved by editing config — no fork.

- [ ] **Step 2: Commit the Team-target config**
